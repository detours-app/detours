Detours chrome direction

Golden Gate-style chrome: dense and fast, but with edge-to-edge sidebars, uniform toolbars, clearer contrast, restrained icons, and stronger active-pane identity.

Prototype interactions

  • Click panes, tabs, sidebar rows, breadcrumbs, toolbar buttons, and file rows. Double-click folders to drill in. Backspace, Return, Up, and Down work on the active pane.
  • The selected tab now has one underline color everywhere. Remote identity lives in the host chip and status text, not in an extra tab color.
  • The single top-right P is Command-P search and navigation: it opens a quick navigation panel scoped to the active pane.
  • i opens a compact inspector for the active selection, including host, path, kind, size, date, and mount/remote context.
  • Back and forward are icon buttons with arrow geometry, not text brackets.
  • Devices includes a mounted sparse bundle and mounted disk image with eject affordances, because those need to scan differently from ordinary folders.

What I would change

  • Make the top chrome feel like a uniform toolbar stack: titlebar, pane tabs, and path bars should align as one system rather than separate strips.
  • Give the active pane one unmistakable signal: flat tab underline, selected-row tone, and status metadata. Keep the inactive pane calmer.
  • Turn remote identity into a first-class chip in the path bar. Host state should be visible without stealing row space.
  • Use folder/file semantics consistently: directories get disclosure, folder shape, and tighter folder row spacing; files keep git/status rails.
  • Use a Golden Gate sidebar: full-height, edge-to-edge shaded column with colored source icons, no floating island or inset plateau.
  • Keep row density, but reduce visual noise with improved contrast, sparse hairlines, and fewer decorative icons.

Implementation bias

  • No marketing gloss, no oversized rounded cards, no decorative background effects.
  • Mostly AppKit-native: SF Symbols, existing theme tokens, current row heights, current keyboard model.
  • Likely small internal additions: semantic colors for active pane, remote chip, hover row, selected row, and sidebar badges.
  • Work in passes: first hierarchy and spacing, then iconography, then sidebar polish, then screenshots across light/dark themes.

External references

  • Apple macOS Golden Gate: Apple calls out uniform toolbars, edge-to-edge sidebars, improved contrast, updated window shapes, and tint control.
  • Golden Gate coverage: public screenshots show the sidebar moving away from Tahoe's floating treatment toward a full-height column with color returning to sidebar icons.
  • Apple HIG: sidebar and toolbar structure should clarify navigation and primary actions, not become decoration.
  • ForkLift 4: dual-pane, remote connections, sync, preview, activity, and Quick Open need clear homes in the chrome.
  • Transmit: server identity and transfer activity deserve first-class UI, not buried status.
  • Marta: native, fast, keyboard-centered, and themeable argues for restraint over ornament.
  • Raycast and Nova: power-user Mac tools can feel precise, premium, and keyboard-first without becoming sparse.
This is intentionally Golden Gate rather than Tahoe: no floating sidebar island, no over-rounded window, no glassy legibility gamble. The app is a power tool; the chrome should get out of the way while still feeling built, not assembled.
